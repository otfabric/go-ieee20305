# Architecture: otfabric/go-ieee20305

How the library is put together: its layers, the rules between its
packages, and how the server, the agent and the generator work inside. For
the public API see [API.md](API.md); for what is implemented see
[INTEROPERABILITY.md](INTEROPERABILITY.md).

## Layers

```
            ┌──────────────────────────────┐   ┌───────────────────────────────┐
 device     │ agent                        │   │ server            (operator:  │  utility
 side       │  events, Responses, metering │   │  handler, Admin    Admin API) │  side
            │  subscriptions               │   │  events, notifier, auth       │
            ├──────────────────────────────┤   │  store                        │
            │ client                       │   ├───────────────────────────────┤
            │  resources, lists, walks     │   │ schedule (EventStatus)        │
            └──────────────┬───────────────┘   └───────────────┬───────────────┘
                           │ HTTPS, mutual TLS (security; CCM_8: tlsccm)
            ┌──────────────┴───────────────────────────────────┴───────────────┐
            │ ieee20305: the resource model, codecs, editions, WADL resources  │
            │ csipaus: the CSIP-AUS types           (generated by internal/gen) │
            ├───────────────────────────────────────────────────────────────────┤
            │ internal/xml: the wire format of both                             │
            └───────────────────────────────────────────────────────────────────┘
```

Both sides share the resource model and nothing else. The model is
generated; everything above it is written by hand.

| `security` | `ieee20305` |

| `csipaus/csipclient` | `client`, `csipaus` |
| `csipaus/csipserver` | `server`, `csipaus` |

The rules, which review enforces:

- The root package knows neither HTTP nor the XML wire format: the wire
  format is `internal/xml`, HTTP is `client` and `server`.
- `client` and `server` do not import each other. The e2e tests and the
  examples join them.
- The module depends on the standard library only (`make nodeps`).
  `tlsccm` and `interop` are modules of their own, so that their
  dependencies stay out of it.
- Generated code (`*_gen.go`) is never edited; the generator and its inputs
  are.

## The resource model and the generator

`internal/gen` turns the pinned upstream files of
[schemas/manifest.json](schemas/manifest.json) into Go:

1. `upstream` downloads the IEEE 2030.5-2023 `sep.xsd` and `sep_wadl.xml`
   and the CSIP-AUS v1.3 schemas, and checks their SHA-256 against the
   manifest. `make check-updates` reports newer upstream releases.
2. `xsd` parses and resolves the schemas: types, derivation, facets,
   cardinalities, defaults, and the elements that IEEE 2030.5-2018 lacks.
3. `wadl` parses the WADL: every resource with its sample path, methods and
   their conformance (mandatory, optional, discouraged).
4. `emit` writes the Go: a struct per type with XML tags in schema order,
   `Validate` methods, `Get…` defaults, the document elements, the resource
   table, the link and list accessors, `Clone`, `Strip2018` (what an
   encoding for 2018 drops), and tests of every type against the schema's
   own examples.

`MarshalEdition` encodes a 2023 document for a 2018 peer by stripping what
2018 does not define. `csipaus` is generated the same way, with its types
embedding the IEEE 2030.5 types they redefine.

## Server

A `server.Server` is an `http.Handler` over a `Store` of `Node`s: an href,
its WADL resource, its document, an owner (the LFDI that may change it) and
its parent. Lists are nodes with members.

**A request** (`handler.go`) goes through:

1. *Identity*: the client certificate's LFDI (`PeerCertificates`), and the
   device the server was told of (`device.go`): its role and edition.
2. *Routing*: the path matched against the sample paths of the WADL; a
   method the WADL does not allow for the resource is 405, as are the
   discouraged ones unless enabled.
3. *Authorization* (`auth.go`): a device reads what is shared and its own
   resources, and changes only its own; an aggregator acts for the devices
   it manages; an operator acts for everyone.
4. *Handling*: `Hooks` of the resource if any; otherwise the default GET
   (lists paged and ordered as the standard orders each list), PUT
   (replace, keeping the server's links), POST (create an item with its
   parts: `parts.go`) and DELETE.
5. *Dressing* (`links.go`): every document gets its href, every ListLink its
   `all`, and links to resources the server does not have are dropped.
6. *Encoding* in the edition of the device.

**Parts.** Creating a resource creates its parts: an EndDevice its
FunctionSetAssignmentsList, DERList, LogEventList, SubscriptionList, …; a
DERProgram its DERControlList, ActiveDERControlList, DERCurveList and
DefaultDERControl. Parts a device creates later by PUT (a DERSettings) exist
as linked nodes without a value.

**Computed resources** (`virtual.go`): the Active lists and the
CurrentDERProgram are computed from the events when they are read.

**Events** (`events.go`): a `schedule.Scheduler` per function set holds the
server's events, without randomization. Its transitions write the
EventStatus of each event (Scheduled, Active, Completed, Cancelled,
Superseded), under the event's node lock so that an operator's PUT and a
status change do not lose each other. Ended events are pruned after
`EventRetention`.

**Responses and metering** (`metering.go`): a Response is stored once per
device, event and status (`OnResponse` is told once). A MirrorUsagePoint
becomes a UsagePoint; MirrorMeterReadings become MeterReadings, ReadingTypes,
ReadingSets and Readings. `FlowPolicy` answers FlowReservationRequests.

**Notifications** (`notify.go`): the Store is wrapped so that every change,
by a device, by `Admin` or through the Store, marks the subscriptions whose
resource it touches. Each subscription has a worker that posts the resource
as it is when the worker runs: bursts coalesce into the latest state, which
arrives at least once and never before an older one. Delivery retries by
`NotificationRetry`; a 4xx, or failures for longer than
`NotificationCancelAfter`, cancel the subscription.

**Locking** (`keylock.go`): one lock per list or node, taken for the
read-modify-write of a list (hrefs, caps) or a node (event status), so that
devices do not serialize on each other.

## Agent

An `agent.Agent` runs on a `client.Client`:

1. `Start` reads DeviceCapability and Time, finds or creates the EndDevice,
   waits for its Registration and checks the PIN.
2. A poll loop re-reads the FunctionSetAssignments and their programs at
   the server's pollRate (slower when subscribed), with `Backoff` on
   failures. Errors that waiting does not fix (4xx, certificates,
   configuration) end `Run`.
3. Per function set, an event set (`events.go`) upserts the events it reads
   into its own `schedule.Scheduler`, with randomization and the function
   set's conflict rule, and passes each transition to the handler
   (`OnDERControl`, …).
4. The Responses the events ask for go through a queue that retries
   failures and drops what the server refuses with a 4xx.
5. Metering (`metering.go`) creates the mirror once and posts readings at
   `PostRate`, buffering a bounded number while the server fails.
6. With `NotificationURI` (`subscribe.go`), the agent subscribes to its
   FSAs, programs and controls, and a notification wakes the poll loop.

## Testing

| Layer | Where | What |
|-------|-------|------|
| Unit | `*_test.go` beside the code | Every package, with the race detector; generated types against the schema's examples and, with `xmllint`, against `sep.xsd` |
| Fuzz | `make fuzz`, nightly in CI | Codecs, the server handler, HardwareModuleNames, scheduling, DNS messages, hrefs |
| End to end | `e2e/` | Agents against the server over mutual TLS: every function set in both editions, chaos (lost, replayed and truncated requests, 503s, resets, clock skew), 500 agents at once, notification storms, goroutine leaks |
| Interop | `interop/` module, the Interop workflow | The client against Envoy and GridAPPS-D, and the GridAPPS-D, py20305 and EPRI clients against the server ([README](README.md#interop-tests)) |
| Docs | `make features` | [docs/FEATURES.md](docs/FEATURES.md) names only tests that exist |

Statement coverage of the library is gated at 90% (`make coverage-gate`).
